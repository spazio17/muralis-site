The panel on the wall
looks after itself.

Muralis turns an Android tablet into a wall-mounted Home Assistant dashboard: locked to the one page you want, recovering on its own when that page goes stale or unreachable, and answering to MQTT and HTTP so the panel is one more thing your house can control.

It installs as an ordinary APK on stock Android. No root, no custom ROM, no platform signature — nothing to rebuild the next time the tablet takes an update.

What it is

A kiosk launcher, not a dashboard. You bring the dashboard — a Home Assistant view, or any web page you like. Muralis is the thing that keeps a tablet showing it, month after month, without anyone walking over to it.

The problem

Wall panels drift

A browser left open for weeks stops repainting. A Wi-Fi blip leaves an error page. An update reboots the tablet into its own launcher. Every one of those ends the same way: a dead panel on the wall and someone fetching a chair.

The approach

One clock owns recovery

A single supervising loop makes every retry and timeout decision. Page callbacks only record what happened — they never trigger a reload themselves. That is deliberate: overlapping timers firing reloads at each other is the failure this design exists to avoid.

The result

It comes back by itself

Failed loads retry on a bounded schedule. A hung load times out. The dashboard is recycled nightly and under memory pressure. A page that has stopped changing for fifteen minutes is reloaded. After a reboot the app is the home screen, so the panel returns on its own.

What it does

Two remote surfaces over one command set, telemetry your automations can act on, and a way back out that does not need a cable.

MQTT and HTTP, one behaviour

Both surfaces call into the same command dispatcher, so kiosk.reload, set_url, display.brightness, system.reboot and the rest behave identically no matter which one they arrived on.

A refused command is never silent. Bad arguments come back rejected; a command this build does not implement comes back unsupported. You can always tell a refusal from a dead panel.

Home Assistant, natively

MQTT discovery announces the panel and its controls, so entities appear without hand-written YAML. Availability is backed by the broker's Last Will, which means the panel reads as offline even when it lost power with nothing left running to say so.

Telemetry worth automating on

Battery, charge state and temperature; memory and swap; storage; network type, signal and link speed; CPU load and thermal status; uptime; brightness; and the dashboard's own load state and crash count.

Published on an interval you pick — 10, 30, 60 or 300 seconds — and early, ahead of that interval, for the handful of fields that matter immediately.

A built-in web admin

Every setting, plus a live status page, served from the tablet itself on your local network. Useful precisely when the panel is misbehaving and you would rather not take it off the wall.

A recorded way out

The escape hatch is a series of corner taps you record yourself — three to twelve, across the four corners of the screen, with separate combinations for "open settings" and "exit to the launcher".

Recordable rather than fixed, because a gesture is worthless once someone has watched it being used, and a hardcoded one is the same on every panel ever shipped.

Off until you turn it on

Neither remote surface ships a default credential and neither activates on its own. The web admin binds no socket at all until an administration password of at least eight characters exists. MQTT starts once a broker address is set.

Broker credentials and the admin password are stored as AES-GCM ciphertext under a key that never leaves the Android keystore.

Screens

The tablet UI, the web admin and this site all take their colours from the same Catppuccin palette — Mocha in the dark, Latte in the light.

Requirements

Muralis targets the public Android SDK only. Device-owner status is the ceiling of privilege it can reach, and it works without that too — visibly reduced, but working.
Android 8.0 (API 26) or newer. Stock Android is fine; a custom ROM is not needed.
Installation An ordinary APK. No root, no platform signature, no privileged permissions.
Full kiosk behaviour Needs device-owner status, granted either over adb or by QR provisioning during out-of-box setup. That unlocks becoming the home app, lock task, hiding the status bar and notification shade, disabling the lock screen, and remote reboot.
Without device owner Still runs, still recovers, still answers MQTT and HTTP. The system UI stays reachable and reboot is unavailable — the app says so rather than pretending otherwise.
Dashboard Any web page. A Home Assistant view is the intended case, and a LAN-only install works — Muralis never waits on a route to the internet.
MQTT broker Optional. Any broker, with or without credentials. Connections are unencrypted, so run it on a network you trust.

Availability

Muralis runs on real hardware today and is in daily use on the panel it was written for. It is not published yet, and there is nothing here to download.

Pre-release. There is no signed release build and no store listing. When there is, this page will carry the download and the provisioning QR, and not before — a QR code pins the signing certificate of the exact APK it was made for, so publishing one early would only fail verification on your tablet, late in setup, with a message that does not explain why.
